# Otec data utilities

Run from the repository root with the locked Python dependencies:

- `make data grid`: official FABDEM ground on the aligned 10 m grid, Copernicus comparison raster and core OSM features. Existing grids can be migrated explicitly with `uv run --frozen --no-env-file python -m sim.fabdem download`, then `uv run --frozen --no-env-file python -m sim.fabdem switch` and `make export`. Recompute datum calibration and replay after changing ground. FABDEM attribution and inherited Copernicus attribution are preserved in provenance; see the root README.
- `scripts/export_fabdem.js`: Earth Engine fallback for the exact FABDEM AOI tile; requires your own login/project and version verification before naming the export V1-2. Public Bristol range extraction is the default and needs no login.
- `make context`: public OSM river, water, green polygons and existing tagged road geometry.
- `make buildings`: public Google Open Buildings v3 AOI extraction, 2023 Temporal raster sampling, median-height enrichment and web export.
- `scripts/export_open_buildings_2023.js`: optional Earth Engine Code Editor fallback; requires your own login/project. Exact output handoff paths are in the root README.

Downloaded inputs are cached under `data/raw/`. Incomplete transfers remain `.part` files and never count as ready. No flood inputs are generated by these utilities.

For flood runs, `make calibrate` and `make replay` retain static connected-stage July 2023 reconstruction and Sentinel-1 scoring. `uv run --frozen --no-env-file python -m sim.dynamic check` reports exact missing prerequisites. Once ready, `make whatif` computes separate dynamic virtual-pipe scenarios from the calibrated static baseline. Scenario definitions can be written with `uv run --frozen --no-env-file python -m sim.dynamic definitions`; they are clearly hypothetical and do not count as simulated water output. Runtime, exposure and water-balance values are written only by completed runs. Counterfactual satellite overlap remains null.

For the separate Texas Drone proof tab, read [drone_proof.md](drone_proof.md) and [drone_proof_manifest.schema.json](drone_proof_manifest.schema.json). Check availability with `uv run --frozen --no-env-file python -m sim.drone_proof status`. Confirmed DJI footage/telemetry and matching USGS LiDAR are currently missing; the utilities do not substitute another flight or reuse older dense products. The guide covers source provenance, native tools, fresh runs and independent held-out validation. Actual metrics are published only to `runs/drone_proof/metrics.json` after validation succeeds.

Mapbox imagery is optional display-only context, with adaptive zoom and a 96-texture resident cap; it cannot change exported scientific rasters or metrics. The exact-file launcher is `uv run --frozen --no-env-file python -m sim.serve --mapbox-token-file "<exact-approved-path>"`. Use it only for the specifically approved file read. It selects `VITE_MAPBOX_TOKEN` or the `MAPBOX_TOKEN` fallback without shell evaluation and starts without auto-reload. No environment files are discovered, created or loaded implicitly; `make serve` uses the launcher without a file argument and can inherit an already supplied process variable. Satellite roof colour and procedural wall windows are rendering details, not measured height or façade inputs.

Measured verification and current input gates are tracked in [docs/diorama-check.md](../docs/diorama-check.md).
